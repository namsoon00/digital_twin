# 가설 검증 개선: 구현과 데이터 검증

검증일: 2026-09-28. HYP-00~09를 기존 관측 원장, 가설 개발 큐, 릴리스 제어 경로에 연결했다. 아래 실제 데이터 수치는 고정한 제한 표본의 결과이며 전체 과거 성과나 투자 수익의 증명이 아니다.

## R1 — 평가 신뢰도 (HYP-00~03)

- `outcome-interval-selection-v2`는 계좌·종목·가설 지문·측정 기간별로 최초 관측을 고정한다. 중복 사건과 실제 결과 구간 중첩을 제외하며 최초 결과가 실패·결측이어도 후속 승자로 교체하지 않는다.
- 1시간·24시간 등 기간을 분리한다. 계좌별 판단 평가와 시장 사건을 계좌 간 합친 예측 평가도 구분한다. 비중첩만으로 시장 표본의 통계적 독립성이 입증되지는 않는다.
- 자격은 정확한 가설/결과 계약 지문에 연결한다. 기존 ABox 집계에는 재구축 필요 상태를 표시한다. 여러 계좌·종목의 자격을 전역 active로 합치지 않는다.
- 신규 작성 정책 v2의 active에는 같은 가설의 기준선 비교 합격 영수증도 필요하다. 기존 릴리스의 동결 정책 v1을 소급 변경하지 않는다.
- DB 성과 조회에서 원래 최종 AI 판단을 보존한다. 향후 판단은 실제 추론 추적 품질을 기록하며, 근거 없는 주장·중복 발송·중요 사건 누락은 레이블이 없으면 미측정으로 남긴다.
- 기존 성과용 요약 저장소의 v2 형식에는 가설 계약, 원래 AI 평가, 품질 측정값만 보관한다. 큰 원본 판단 JSON과 프롬프트를 반복해서 읽지 않는다. 원본 수정 시각과 형식 버전이 맞아야 요약을 사용하고, 기존 복구 워커와 원자적 저장/롤백 경로를 유지한다. 기존 `hypotheses_json` 컬럼은 v2부터 이 명시적 객체를 담으며 별도 스키마 변경은 없다.

데이터 검증: 판단 1,045건 / 결과 2,476건의 고정 입력을 두 번 계산해 완전 일치를 확인했다. 정확한 버전·계좌·종목·기간 집계 118개에서 중첩 444건, 가설 버전 미확인 70건, 결과 부적격 35건, 관측 구간 미확인 4건, 중복 사건 2건을 제외했다. 이 제외 수는 해당 집계 범위의 값이며 전체 원장 삭제 건수가 아니다.

초기 규칙 59개의 자격 미리보기는 shadow 58개, observed 1개였다. 이후 출시 전 의미 감사에서 고베타와 고PER을 묶은 항목을 예측에서 제외해 현재 활성 예측 규칙은 58개다. 원본 active 1개 / limited-active 1개를 새 성과로 자동 상속하지 않았다. 최종 AI 판단 가격 결과 12건이 저장소 조회 후 평가에 남는 것을 확인했다. 과거 비서 품질 레이블은 0건으로 미측정이다.

## R2 — 측정 계약과 그래프 연구 (HYP-04~05)

- 사건·재무·가치 가설의 측정 대상, 원천, 기간, 최소 표본 수, 자료 보존 요구를 계산한다. 30일 안에 필요한 독립 표본을 만들 수 없는 장기 설계는 장기 연구 계약이 필요하다고 차단한다.
- 가치 괴리는 두 시점의 실제 불변 valuation bundle로 측정한다. 모델·가정 버전·통화가 같고 재현 가능해야 한다. 가격 변화와 가치 추정 변화의 기여를 분리하며 인과관계로 표시하지 않는다.
- 결과 워커는 기준 시각까지 실제 저장된 재무/가치 원천만 읽는다. 현재 자료로 과거 결측을 채우지 않는다. 지연 관측과 검토 기간을 실험 보존에 반영한다.
- 가설 작성 큐에 현재 시각의 별도 연구 입력을 제공한다. 계좌·종목·ABox 스냅샷·추론 세대, 관련 TBox 의미, 근거·반례·출처·생략 범위를 기록한다. 제안 당시 근거와 현재 연구를 섞지 않는다.
- 최대 40개 ABox 사실, 사실 본문 18KB, 추론 20개, TBox 의미 12개로 조회를 제한한다. 조회 안 함, 조회 실패, 세대 미준비, 빈 결과, 반례 발견을 구별한다.

데이터 검증: 비활성 규칙도 포함한 예측 계약은 의미 감사 전 72개, 감사 후 71개다. 현재 활성 설계 58개와 측정/기간 보완 필요 13개를 구분했다. 선택 종목의 실제 그래프 연구 조회는 공개된 해당 종목 추론 세대가 없어 `not-evaluated`였다. 이를 근거가 충분한 상태로 바꾸지 않았다. 계좌 혼입, 미래 자료, 조회 중 스냅샷 변경, 가치 괴리가 오히려 확대되는 사례를 회귀 검증했다.

## R3 — 작성 범위와 조건부 비교 (HYP-06~07)

- 기존 16개 모델 / 32개 조건 절단을 제거했다. 실제 등록 이름인 `subject_property`를 인식하도록 고쳐 누락된 종목 속성 조건도 포함했다. 현재 122개 규칙에서 활성 예측 규칙 58개와 추가 조건 110개가 작성 기능 목록에 들어간다. 이 숫자는 독립 AI 모델 수나 성과가 입증된 가설 수가 아니다.

## 출시 전 의미 감사

`npm run python:hypothesis:audit`는 활성 예측 규칙 전부에 대해 모델 신호, 가설군, 주장, 예상 방향, 결과 지표, 기간, 반증 조건과 필수 관측을 한 번에 출력한다. 감사 계약은 신호와 가설군의 일치, 주장 카탈로그 일치, 결과·반증 기준 존재 및 가치 가설의 비교 가능한 가치 괴리 측정을 검사한다. 현재 활성 예측 규칙 58개가 모두 이 계약을 통과하며 누락 규칙은 0개다.

- `고베타 또는 고PER` 결합 규칙을 제거했다. 베타는 기존 시장 민감도 문맥으로 유지하고, 높은 PER은 가치평가 점검 문맥으로만 사용한다. 둘 다 단독으로 가격 방향을 예측하지 않는다.
- 악재 흡수는 우호 사건 확산과 분리한 `event-absorption` 가설이다. 부정적 사건, 사건 이후 가격 방어와 후속 60분·1일 초과수익을 연결하며 우호 뉴스 성과를 상속하지 않는다.
- 호재 뒤 가격 약세는 일반 추세 훼손이 아니라 `event-rejection`으로, 위험 사건 집중은 `event-risk`로 분류한다.
- 안전마진과 음의 안전마진은 실적 개선·악화의 대용치로 사용하지 않는다. 동일 모델·버전·가정·통화의 두 불변 가치평가 묶음으로 가치 괴리 수렴과 확대를 각각 측정한다.
- 사건 모델과 가치 모델 릴리스 ID를 새 버전으로 올렸다. 바뀐 규칙 ID와 claim fingerprint는 기존 평가 이력을 새 의미에 합산하지 않는다.

부작용으로 이전보다 예측 후보가 한 개 줄고, 가치평가 묶음이 두 시점 모두 없으면 가치 가설은 `판단 불가`로 남는다. 이는 출시 전 의도한 보수적 변경이다. 기존 저장 판단과 결과는 수정하지 않는다.
- 등록된 타입·단위를 유지하는 숫자 임계값, 기존 시차/추세 조건, 최대 8개 추가 조건 조합을 지원한다. 새로운 수집기·지표·임의 시간 창은 개발 요구로 남긴다.
- 같은 예측에 조건만 추가한 후보는 새 동결 selection contract로 비교한다. 최초 기준선 기회 전체를 고정하고 선택, 회피, 판단 불가를 보존한다. 회피한 실패뿐 아니라 놓친 성공도 계산한다.
- 회피는 실제 조건 불충족 증명이 있어야 한다. 후보 부재, 입력 누락, 대상 불명확, 실행 실패는 판단 불가다. 연구용 기회 원장은 투자 판단이나 HOLD를 만들지 않는다.
- 성과는 예측 정답 +1 / 오답 -1 / 회피 0의 분류 효용이다. 거래 비용·포지션·체결이 없는 이 값을 투자 수익률로 표시하지 않는다. 표본, 불확실성, 반복 작성 보정을 적용한다.

검증: 선택 없는 동일 예측은 합격하지 않는다. 유리한 회피와 불리한 기회 손실을 함께 계산하고 최초 결측을 나중 표본으로 교체하지 않는다. 지연 결과의 실제 중첩, 실험 원장 저장/조회/중복 재시도도 검증했다.

실제 TypeDB 추가 조회에서는 미지원 속성의 스키마 오류와, 등록된 후보 입력을 이용한 인덱스 없는 조회의 3초 시간 초과를 확인했다. 이 조회들은 회피 증명을 생성하지 않았다. 입력 증명 생산/압축/원장 연결은 회귀 테스트로 확인했지만, 이 시점의 실제 조건부 회피 관측이 확보됐다고 주장하지 않는다.

조건부 후보의 native 실행은 같은 ABox 쓰기 잠금 아래 TypeDB 입력 존재 확인 쿼리를 추가로 수행한다. 전체 조건 쿼리는 불충족이고 모든 참조 입력은 존재하는 종목에만 부정 증명을 남기며, 이 증명은 추론 압축과 관측 원장까지 전달된다. 최대 20종목, 32조건, 추가 조회 2초로 제한한다. 부재 조건·참조값 기본값·미지원 속성·조회 실패·다른 실행 경로는 `unknown`으로 남는다. 실행 성공·매칭 0건만으로 결측과 조건 불충족을 구별하지 않는다. 이번 실제 시험 후보는 기존의 상반 예측 비교 계약을 사용한다.

## R4 — 실제 후보와 설명 화면 (HYP-08~09)

- 개발 사례 34건을 최초 기준으로 종료 2건, 명세 수정 30건, 미지원 기능 2건으로 분류했다.
- 기존 사례 1건에 명시적 계약 수정을 적용했다. 이전 작성 3회 이력을 유지하고 누적 4회 / 계약 수정 1회로 기록했다. 종료 사례는 다시 열지 않았다.
- 실제 TypeDB에서 후보 규칙 1개를 검증했다. 쿼리 성공 / 매칭 0건은 성과 성공이 아니다.
- 기존 동결 TBox와 무관한 최신 TBox 타입이 실험 등록을 막는 문제를 수정했다. 기존 TBox를 보존하며 후보가 실제 요구하는 타입이 빠져 있으면 여전히 차단한다.
- 후보를 운영과 분리된 실험 릴리스에 등록했다. `shadow-observing`이며 확인 시점의 시작 제한은 `experiment-inference-not-observed`였다. 최초 입력·미래 결과는 각각 0건이다.
- 검증 게이트 12개 중 8개 통과, 3개 대기, 차단 0개, 비차단 상태 1개였다. 현재 재생·미래 관측·추가 검증을 통과한 것으로 표시하지 않는다. 운영 채택이나 알림 권한은 바꾸지 않았다.
- 관리 화면은 카탈로그 등록, 현재 매칭, 경험적 자격, 운영 배포를 구분한다. 관측 기간·보존 요구·제외 이유·다음 부족 자료 및 최종 AI/비서 품질을 보여준다. 최근 최대 500건 보고서에 전체 이력 대표성이 없음을 표시한다.
- 성과 HTTP 조회는 읽기 전용 설정을 사용해 화면을 여는 동안 운영 스키마 초기화나 이력 정리가 실행되지 않도록 했다. 품질 보고서가 늦어도 개발 사례 목록을 먼저 표시한다.

## 재검증

`npm test`가 구문/프런트엔드/HTTP smoke/Python core를 실행한다. 핵심 추가 테스트는 `test_hypothesis_evaluation_v2.py`, `test_hypothesis_research_pipeline.py`, `hypothesis-research.test.mjs`에 있다. 기존 실험·진화 테스트는 채택, 기각, 사후 악화 복원과 동결 릴리스 경계를 확인한다.

최종 전체 `npm test`는 Python 1,648개, 프런트엔드 50개 및 HTTP smoke를 모두 통과했다. 별도로 런타임 조립/백엔드 연결 27개, 숫자 조건 작성 26개, 원본 AI 판단 보존·요약 재구축·트랜잭션 저장 관련 테스트도 통과했다. 첫 실제 서비스 조회의 지연과 시간 초과를 확인한 후 아래 보완까지 포함해 전체 검증을 다시 실행했다.

재시작 뒤 원본 JSON 반복 추출로 발생한 HTTP 시간 초과를 추가 보완했다. 화면은 전용 읽기 서비스로 최대 500건만 평가하고 전체 모집단 집계를 호출하지 않는다. 요약 500건 재구축 후 원본 SHA-256 500개가 모두 일치했다. 별도 로컬 검증 서버에서 실제 API는 HTTP 200 / 10.49초 / 평가 500건 / 최종 AI 가격 결과 12건 / 품질 레이블 0건을 반환했다. 이 시간은 당시 동시 부하의 관측값이며 응답 시간 보증은 아니다.

실제 원장 표본·사례 원문·계좌 식별자는 git에 포함하지 않는다. 검증 파일은 로컬 임시 디렉터리에만 저장했다. 미래 관측은 실제 시간이 흐르고 해당 원천/추론이 도착해야 쌓이며, 개발 테스트를 통과했다고 투자 성과를 입증한 것은 아니다.
