# Notification Terminology

알림 메시지와 설정 화면에서는 투자 모델의 판단값과 알림 발송 정책값을 분리해서 표현한다.

## 관계 판단

- 사용자 표시명: `관계 판단`
- 상태 표시명: `확인 단계`
- 목적: 종목을 매수 후보, 매도 후보, 보유 점검 대상으로 볼지 관계 규칙과 근거로 판단한다.
- 대표 값: `reviewLevel`, `dataState`, `changeState`, `conflictState`, `validationState`
- 대표 규칙: `ontologyRelationRules`
- 메시지 내용: 모델명, 엔진 버전, 성립 규칙, 근거, 부족 데이터, AI 프롬프트
- 금지 표현: 점수·확률처럼 보이는 `관계 점수`, `발송 점수`, `꿀점수`

기존 점수 기반 공식은 읽기 호환을 위한 과거 입력일 뿐이며, 새 판단·알림·관리 화면에는 저장하거나 표시하지 않는다. 운영 MySQL의 `notification_rules`도 상태 조건·유사 알림 억제·쿨다운 값만 보관하며, 과거 점수 열은 시작 시 마이그레이션으로 제거한다.

## 알림 발송

- 사용자 표시명: `알림 발송`
- 운영 표시명: `발송 상태`
- 목적: 이미 감지된 이벤트를 실제 텔레그램/웹 알림으로 보낼지 판단한다.
- 내부 운영 값은 발송 순서와 중복 억제에만 쓰며 투자 판단에 사용하지 않는다.
- 메시지 내용: 발송 이유, 쿨다운 해제 사유, 발송 상태, 부족 데이터만 표시한다.
- 금지 표현: 투자 모델처럼 보이는 `모델링 점수`, `점수 계산`, `꿀점수`

### 알림이 온 이유

- 답하는 질문: `왜 지금 이 메시지가 발송됐는가?`
- 단일 기준: 최종 발송 게이트 뒤에 확정된 `CustomerDeliveryExplanation`
- 표시 순서: 주 발송 계기 1개, 필요한 보조 설명 최대 2개
- 허용 계기: 검증·재발송 같은 명시적 운영 요청, 최종 AI 행동 변화,
  검증된 판단 차단·복구, 새 판단 원문, 거짓에서 참으로 전환된 명시적 기준,
  최초로 완료된 보유 종목 최종 AI 판단
- 별도 표시: 투자 판단 근거는 `핵심 근거`, 규칙과 성립값은 `TypeDB 검토 가설`
- 금지 표현: 규칙 이름 나열, TypeDB 식별자, 그래프 fingerprint, 내부 영문 diff,
  실제 전이가 없는 `판단 변경` 표현

검증·재발송은 새 투자 신호로 표현하지 않는다. 검증 메시지는 검증 목적과
새 투자 신호가 아니라는 사실을 표시한다. 재발송은 원본 본문을 보존하고
재발송 envelope와 원본 이벤트를 별도로 추적한다.

`ABSTAIN`, AI 실행 실패, TypeDB 폴백, 자료 준비 상태만의 변화는 웹 이력으로 남긴다.
`REVIEW_ONLY`는 매매 판단 권한이 없다는 뜻이며, 무조건 알림 금지를 뜻하지 않는다.
검증된 AI가 지배 가설·인과 경로·투자 의미·다음 확인 조건을 설명하고,
첫 유효 인사이트, 관점의 실질 변화 또는 아직 재분석하지 않은 검증된 확인 조건 전이가
있을 때는 `AI 해석`으로 발송할 수 있다. `NO_ACTION`을 보유나 매매 지시로 바꾸지 않는다.
`투자 판단`은 별도로 `FINAL_DECISION`과 검증된 행동 권한을 충족해야 한다.

최종 AI 정책은 `decisionReconciliation`에 대상 계정·종목·후보·ABox·추론 세대·예약된
알림 번호와 함께 기록한다. 발송 큐와 발송 직전 검사는 이 검증된 정책을 재사용하며,
매매 가설의 검증 대기를 이유로 허용된 해석을 다시 차단하지 않는다. 계정 발송 설정,
중복 제거, 쿨다운 및 전송 성공 확인은 계속 별도로 적용한다.
`semanticReasonCode`는 AI 정책의 사유, `reasonCode`는 실제 큐 접수 결과의 사유다.
큐 접수 이후 전송 단계의 차단도 종목 판단 기록에 실제 사유를 남기며, `queued`를
실제 발송 완료로 표시하지 않는다. 과거 알림을 자동 재발송하지 않는다.

## Message Layout

투자 판단과 알림 표시는 분리한다. TypeDB 추론, AI 대안 비교, 근거 검증은 항상 전체로 실행하고 저장한다. 텔레그램에는 계정의 `notificationDetailLevel`에 따라 필요한 설명만 선택하며, 웹 상세에서는 전체 판단과 추적 기록을 확인한다. 투자 경험 수준인 `messageDeliveryLevel`은 용어 난이도만 바꾸고 정보량을 결정하지 않는다.

알림의 첫 줄은 `아이콘 알림 종류 · 종목/대상` 형식을 사용한다. `시세 변화`, `관계 변화`, `AI 해석`, `투자 판단`을 구분하며, 투자 행동은 앞단에서 검증된 본문에 표시한다. 종류와 아이콘은 `domain/notification/presentation.py`의 공통 목록으로 관리한다. AI가 설명을 작성했다는 이유만으로 투자 판단으로 승격하지 않으며, 후보만 달라졌다면 최종 행동 변경이라고 표시하지 않는다. 자세한 계약은 `docs/notification-presentation-contract.md`를 따른다.

`시세 변화`는 가격 변동 사실만 전달하는 `marketObservation`의 표시명이다.
TypeDB 관계 분석을 전달하는 `investmentInsight`는 `관계 변화`로 표시한다.
가격·손익 또는 연결 자산 가격이 분석 계기여도 단순 시세 알림으로 다시 분류하지 않는다.
`관계 변화`는 분석 종류를 구분하는 제목이며 실제 관계 변화 여부는 본문에 표시한다.
`ontologyRelationDiff`가 동일하면 `관계 유지`, 중요하지 않은 맥락 변화라면 그 차이를
명시하며 새 관계나 투자 행동 변화가 생긴 것처럼 표현하지 않는다. TypeDB 참고 관찰은
대표 규칙뿐 아니라 함께 성립한 규칙과 판단에서 제외된 참고 규칙을 구분해 보여준다.
여러 규칙이 실행됐다는 사실을 대표 규칙 하나의 투자 판단으로 포장하지 않는다.
검증된 AI 해석과 최종 투자 판단은 각각 기존의 `AI 해석`, `투자 판단` 분류를 사용한다.

1. `간결` 기본값: 앞단에서 제공한 현재 행동, 실제 변화, 핵심 근거와 다음 판단 조건 중 있는 항목만 표시한다. 선택 섹션 누락만으로 발송을 막거나 빈칸을 보유 의견으로 채우지 않는다. 투자 판단의 근거·행동 검증은 앞단에서 유지하며, 템플릿은 검증된 결과를 바꾸지 않는다. 판단 신뢰도에 영향을 준 데이터 한계만 경고한다.
2. `표준`: 간결 항목에 현재 흐름, 선택된 TypeDB 추론, 회사 가치 요약을 추가한다.
3. `전체`: 기존의 모든 판단 계층과 추적 정보를 알림에도 표시한다.
4. `웹 상세`: 정보량 설정과 관계없이 현재 흐름, 시간축, 경쟁 추론, 회사 가치, 포트폴리오, 사건, 제외 정보, 자료 상태, 이력, 추론 추적, 원문을 보존한다.

간결·표준 알림은 값이 없거나 판단에 사용되지 않은 섹션을 생략한다. 일반적인 자료 상태와 API 진단은 웹 상세에만 둔다. 데이터 누락이 최종 행동의 확신이나 실행 가능성에 실제 영향을 준 경우에만 알림에 `판단에 영향을 준 데이터 한계`로 표시한다.

기사 요약은 제목을 요약으로 재사용하지 않는다. 본문 기반 한국어 요약이 없으면 `기사 본문 요약이 아직 준비되지 않았습니다`라고 표시하며, 같은 URL의 헤드라인·연구 근거 레코드는 병합해 가장 풍부한 본문 분석을 보존한다.

발송 상태는 투자 판단을 뜻하지 않는다. 반복 억제와 유사 메시지 차단을 거친 운영 결과다. 장 시간과 신선도는 발송을 막지 않는 참고 정보다.

AI 의견은 검증된 구조화 응답만 메시지에 반영한다. 연결된 공시/뉴스가 없으면 추정하지 않고 가격, 수급, 추세 중심으로 설명한다. 기사 AI 요약은 사건·주체·핵심 수치·종목 관련성을 완전한 한국어 문장으로 작성하고, 영향 판단과 분리한다. 프롬프트는 `aiPromptTemplates`에서 알림 타입별로 관리한다.

## 문장 근거 계약

- 투자 관점, 이번 변화, 핵심 근거, 반대 근거, 다음 판단 조건, 데이터 한계의 각 문장은 저장된 `evidenceId`를 가져야 한다.
- `support`와 `counter` 문장은 판단에 사용할 수 있는 근거만 연결한다. 참고 전용 기사, 오래된 값, 수집 실패, 미지원 데이터는 행동 근거로 승격하지 않는다.
- 미수집·누락·미지원 정보는 `limitation`으로만 표시한다. 데이터가 없다는 사실을 반대 근거나 보수적 행동의 확정 근거로 쓰지 않는다.
- 행동명 자체를 핵심 근거로 반복하지 않는다. 확인된 반대 사실이 없으면 `반대 근거` 섹션을 생략한다.
- AI 문장에 포함된 수치는 연결된 근거 원장에서도 확인돼야 한다. 근거가 없는 수치나 근거 역할이 맞지 않는 문장만 제외하고 나머지 검증 문장은 발송한다.
- 실제 AI 응답이 근거 연결 계약을 충족한 경우에만 `[AI]`로 표시한다. TypeDB 또는 시스템 폴백은 해당 작성 주체를 그대로 표시하며 AI 의견으로 포장하지 않는다.
- TypeDB 참고 관찰은 최종 행동 주체가 TypeDB인 상태를 유지한다. AI를 사용하더라도 관계 변화를 설명하는 역할만 맡고 투자 행동을 다시 선택하지 않는다.
- 관계 수명주기 알림은 `새 관계가 성립함`, `관계 근거가 강해짐`, `관계 근거가 약해짐`, `이전 관계가 해제됨`, `관계 근거가 만료됨`으로 표시한다. 선택 가능한 투자 가설이 없는 해제·만료 알림은 반드시 `NO_ACTION`이며 매수·보유·매도 표현을 붙이지 않는다.
- 전체 근거 원장, 문장별 검증 결과, 작성 주체, 모델·프롬프트·요청 ID는 알림 시점 스냅샷에 저장하고 웹 상세에서 조회한다.

## 최종 추론 상태 변경

- 사용자 표시명: `추론 상태 변경`
- 비교 단위: 계정과 종목이 같은 직전 `DecisionEpisode`와 현재 최종 AI 판단
- 비교 항목: 권장 대응, 확인 단계, 자료 상태, AI 검증 상태
- 발송 원칙: 최종 AI 행동, 사용자에게 표시되는 판단 차단·복구, 검증된 후속 조건,
  새 판단 원문 중 하나가 실질적으로 바뀐 경우에만 알린다. 자료 상태·AI 검증 라벨·
  그래프 후보만 바뀌고 최종 행동이 유지되면 웹 이력에만 저장한다.
- 반복 원칙: 그래프 재생성 ID, 규칙 실행 순서, 원시 점수만 달라진 경우에는 상태 변경으로 보지 않는다.
- 신선도 원칙: 발송 직전 데이터가 기준보다 오래됐으면 경고를 표시하고 계정 재수집을 예약하되 현재 알림도 보낸다. 새 스냅샷은 TypeDB와 AI 전체 판단 경로를 다시 시작한다.

## 후속 조건 전환

- 조건 생성 시점의 값은 `baselineValue`로 기록하며, 이미 조건식이 참이어도 성립
  전환으로 보지 않는다.
- 관찰 가능한 조건은 `previousMatched=false`에서 `currentMatched=true`로 바뀐
  경우에만 `transitionVerified=true`가 된다.
- 생성 시 이미 참인 조건은 한 번 거짓으로 관측되어 `armed`된 뒤 다시 참이 되어야
  성립한다.
- 이전 버전에서 전환 증거 없이 `satisfied`로 저장된 행은
  `legacy-unverified`로 격리하고 알림 근거로 사용하지 않는다.

## 중앙 AI 전환 (2026-10-01)

`aiObservationDiagnostic`은 **검증 미통과 초안**으로 표시하는 운영 알림이다.
AI가 발송을 제안했으나 검증에서 보류된 문장과 보류 이유, 당시 입력 시세를 보여준다.
검증기의 오차단도 확인할 수 있도록 원문을 보존하며, 이 원문을 검증된 투자 해석으로
표시하지 않는다. 정상 AI 관찰의 성공 발송·쿨다운·후속 관찰 기준에는 포함하지 않는다.

`aiObservation`은 **AI 관찰**로 표시한다. 수집한 사실, 마지막 발송과의 차이,
가능한 설명(가설), 반대 근거, 다음 확인을 구분한다. 규칙 충족은 발송 조건이
아니다. 기존 규칙 기반 AI 판단 알림의 새 발송은 차단한다. 2026-10-02 수정으로
검증된 TypeDB 관계 변화는 `investmentInsight`의 독립 발송 경로를 사용한다.
AI 호출 없이 저장된 가설·규칙·측정값만 설명하며, 중앙 AI의 발송 이력과 분리한다.
시세 기준 시각과 분석·발송 시각을 구분한다. TypeDB 관찰의 사실 목록은
Position의 `sourceAsOf`·`sourceFetchedAt`·원천 시각 상태·신선도 상태를 보존한다.
가격 coverage가 없는 미국 시세도 원천 시각을 표시하며, `updatedAt`이나 알림 생성
시각으로 대신하지 않는다. 과거 시세는 참고 자료로 표시하고 기존 발송 정책을 유지한다.
가격과 원천 시각은 같은 관측에서 가져온다. 최신 Toss 가격 옆에 보존된 KIS 마감값의
coverage 시각으로 대체하지 않는다. KIS 가격을 선택하면 해당 REST/WebSocket의 출처·
원천 시각·수집 시각도 함께 바꾸며, 누락된 시각을 이전 제공기관 값으로 채우지 않는다.
선택한 가격의 시각이 명시적으로 비어 있으면 미확인으로 표시한다. 기존 발송 본문과
영수증은 다시 쓰지 않는다.

## 읽기 쉬운 관계 변화 메시지 (2026-10-02)

`readable-relation-change-v3`는 변화 한 문장, 시세, 가설별 설명, 투자자별 수급,
거래·체결·대기 주문, 재무 참고, 자료 참고 순서로 표시한다. 가설마다 가능한 의미,
판정 규칙·연결 수치, 다음 확인 조건, 예측 검증 상태를 붙여 보여준다.
수명주기 스냅샷의 가설·규칙 ID로 변화의 대상을 연결하며 한 가설의 해제를 다른
가설에 붙이거나 해제를 주가 위험 해소로 표현하지 않는다. 연결이 없는 과거 기록은
대상을 임의로 보충하지 않는다. 같은 검증 상태도 서로 다른 가설에는 각각 표시한다.

저장된 예상 결과·반증 조건과 **정확히 일치하는 원문**에만 검토된 쉬운 표현을 쓴다.
사용자 작성·새 버전의 다른 원문은 그대로 유지한다. 이 표시는 시장 조건을 판정하거나
동결된 RuleBox의 의미를 수정하지 않는다. 원인 확인 수식과 전체 조건은 웹의 접힌
추론 근거에서 확인하며, 메시지에는 예상 결과와 가설 재검토 기준을 풀어 표시한다.
가설과 직접 연결된 규칙을 우선하며 전체 규칙 목록의 처음 세 개로 대체하지 않는다.
상세 조건은 같은 추론의 저장된 trace에서 복원한다. 분석 신호의 근거값을 보여주되
모델이 사용하지 않은 원시 임계치를 규칙 조건으로 만들어 설명하지 않는다.

- 가격·체결·호가·수급의 기준 시각을 따로 표시하고 장중 추정과 마감 확정을 구분한다.

  `observedFields`에 없는 기본값 0은 자료로 간주하지 않는다. 실제 관측한 0은 유지한다.
  미집계·미지원·미확인은 구분하며 주가×수량으로 순매수 금액을 만들지 않는다.

  재무 자료 갱신을 새로운 실적 발표로 표현하지 않는다.
- 가설의 예상 결과와 예측 검증 단계를 함께 표시한다. 표본 1건의 적중률을 확률이나
  서비스 성과로 표시하지 않는다. 반증 조건과 등록된 자동 추적 조건은 구분한다.
- 문장은 이미 읽기 쉽게 작성된 고정 템플릿이므로 반복적인 초보자용 치환을 거치지
  않고 중급 용어 정규화로 `가설`과 단위·수치를 보존한다. 최종 전송 템플릿도 완성된
  문서를 다시 치환하지 않는다. 작은 양수·음수 측정값을 반올림해 0으로 표시하지 않는다.
  다른 알림의 정보량 설정은 그대로다.
