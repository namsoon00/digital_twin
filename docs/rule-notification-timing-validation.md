# 규칙 알림의 검증 상태와 발송 후 가격 관찰

규칙 조건 충족, 가설 성과 검증, 알림 수신 뒤의 매매 성과는 서로 다른 결과다.
이번 변경은 실제 매매 권한이나 동결된 RuleBox의 임계값을 바꾸지 않는다.

## 검증 자료 연결

동결된 필수 기준이 `ma20DistanceChangePp` 등 파생 추세 수치를 요구하면 해당 수치의
유한한 저장값으로 추세 자료의 존재를 판정한다. 기존에는 기준 계산이 완료됐어도
원시 이동평균이 없다는 이유로 `excluded-contract-data-gap`이 될 수 있었다.
관련 없는 파생값이나 기본값 0만으로 일반적인 추세 자료가 있다고 판정하지 않는다.
과거 결과를 복구할 때는 기존 repair 경로로 원래 관찰 시각·가격·계약·저장 사실을
그대로 재평가한다. 현재 시세로 과거 관찰을 대체하지 않는다.

## 고객에게 보이는 의미

- 성과 기준 미달 가설: ‘성과 재검증 중’을 먼저 표시하고 매매 판단 근거에서 제외된 상태를 설명한다.
- 관찰 단계 가설: ‘검증 중인 관찰’을 표시한다.
- 가설 성과 기준 충족: 수신 후 매매 타이밍과 수익성은 별도 검증이 필요함을 표시한다.
- 관리 조건: 관리 조건의 적용과 매매 시점 검증을 구분한다.

여러 규칙을 합치는 요약에서도 이 표시를 유지한다. 통지 이벤트에는 동결된 검증 상태를
기록한다. 이미 발송된 메시지나 원본 재전송 자료를 다시 쓰지 않는다.

## 성공 영수증 기준의 별도 관찰

1. 검증된 근거 식별자를 가진 가설 알림에 측정 계약을 저장한다.
2. 실제 전달 성공 영수증의 `completed_at`을 기준으로 수집한다. 실패 시도는 제외한다.
3. 전달 이후 5분 안에 저장된 유효한 1분 단위 시세를 첫 관찰값으로 고정한다.
4. 원래 가설의 시간 구간마다 전달 시각 이후 경과 시간을 기준으로 가격을 관찰한다.
   목표 시각부터 5분 안의 시세가 없으면 측정 불가로 남긴다. 휴장 중 값을 만들지 않는다.
5. 동일 영수증 재처리와 오래된 동시 작업이 최초 관찰값을 덮어쓰지 못하도록 저장한다.

`investment_notification_timing`에 별도 저장하며 기존 결과 관찰 주기에서 처리한다.
읽기 API는 `GET /api/investment-brain/notification-timing?accountId=...&symbol=...`이다.
최근 최대 200건의 측정 자료만 반환하므로 전체 모집단 성과 통계로 해석하면 안 된다.

이 값은 저장 시세의 변화다. 주문 가능 호가·실제 체결가·거래 비용을 확인한 순수익이
아니며 `tradeTimingQualified=false`, `netReturnPct=null`을 유지한다. 알림 자체도
상승·하락 방향의 매매 지시로 변환하지 않는다. 비교 전략, 비용, 표본 독립성 및 시장
구간별 성능을 검증한 뒤 별도 승인된 정책으로 적용해야 매매 타이밍의 유효성을 주장할 수 있다.
