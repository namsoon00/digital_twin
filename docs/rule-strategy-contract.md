# RuleBox 단기 전략 계약과 운영

## 당일 수급 원천 계약과 회복 전략

`current-flow-production-v3`는 혼합 시계열 수급 모델과 별개의 당일 원천 조건 모델이다.
기존 `flow-statistics-production-v2`의 참고 전용 제한과 비활성 규칙은 보존한다.
다음 다섯 조건을 `.current-flow.v3` 후속 규칙으로 추가한다: 손실 구간 동반 순매수,
외국인·기관 동반 순매도, 체결·호가 우위,
이동평균 가격 이상/합산 순매수, 가격 상승/합산 순매도.

- 실제 관측 필드만 투영한다. 명시적으로 관측한 0은 유효한 값이며 미수신 기본값은 아니다.
- 투자자·체결·호가 각 공급원의 시각과 수신 시각을 분리한다. 미래·시각 미상·장외·
  10분 초과·명시적 품질 제한은 미검증이다. 기존 원천별 제한이 더 짧으면 그대로 적용한다
  (기본 체결·호가 2분). 시세 시각으로 수급 시각을 대체하지 않는다.
  원천 중 가장 이른 만료 시각을 가설별 모델 근거·TypeDB 판정·발송 재검사까지 보존하며,
  모델 변환이나 발송 대기가 원천의 유효기간을 늘리지 않는다.
- 투자자 수급은 당일 장중 추정값만 사용한다. 개인 미집계는 개인 조건을 충족하지 않는다.
  합산 순매수는 외국인·기관이 모두 관측되고 원천 시각이 일치할 때만 계산한다.
  체결강도는 기존 표본/개장 확인을 통과한 경우에만 사용한다.
  KIS의 실제 `intraday-estimate`·`near-live` 상태와 `orderbook` 자료 키를 사용한다.
  공급원의 갱신 대기·유효 기간 만료는 사용할 수 없으며, 조회/수신 기준 시각은
  공급원이 제공한 거래 시각과 구분해 `sourceTimestampState`에 보존한다.
  신규 계약은 AI 강한 근거용 투자자 프로필 대신 이 개별 추정 자료 검증을 사용한다.
  기존 규칙과 프로필은 바꾸지 않으며, 신규 규칙도 `conditional`이고 문구에 추정임을 표시한다.
- 오래된 자료나 누락은 반대 조건의 성립이나 기존 조건 해제의 증명이 아니다.
- 점수는 정확한 원천 조건의 충족 여부다. 누적 매집, 성공 확률, 매매 수익률로 해석하지 않는다.
  가설별 결과 관측과 계좌·실행 제한은 기존 계약을 그대로 따른다.

별도 국내 전략은 `이동평균 가격 이상+합산 순매수` 관찰 → `매수 체결+매수 호가 우위` 진입 검토 →
`상승 중 합산 순매도` 취소 검토 / `외국인·기관 동반 순매도` 종료 검토를 연결한다.
동시 성립은 기존 충돌 상태이며, 실제 매수·매도 이력을 가정하지 않는다. 전략의 다음 확인
문구와 상태 전이 의미도 RuleBox에 동결한다. 새 모델 근거를 기존 관리 제한보다 우선하지 않는다.

조건값은 기존 원본 규칙을 유지한다. 가격 조건은 5·20·60일 평균 중 하나 이상에
도달한 현재 상태이며, 이전에는 아래였다가 위로 돌파했다는 증명이 아니다.
체결강도 115 이상·호가 불균형 8% 이상은 진입 검토의 추가 조건이고,
괴리는 전일 대비 1% 초과 상승 중 합산 순매도가 확인된 경우다.
순매수·순매도의 부호만으로 매집 강도나 거래 비용 이후의 우위를 주장하지 않는다.

배포는 기존 불변 아티팩트에 다섯 모델 규칙과 네 단계 규칙만 추가한다. 기존 정책 행은
그대로 보존하고 범용 모델 브리지의 정책 소속 목록만 합친다. 후보는 전송 권한이 없다.
원천 사실은 종목당 최대 여섯 개이며 새 네트워크 요청이나 전체 수급 이력 조회를 추가하지 않는다.
같은 종목에서 가격·수급 전략이 동시에 변하면 알림은 각 전략의 이전/현재 상태와
다음 확인 조건을 함께 표시한다. 첫 전략만 표시하면서 나머지 변화까지 발송 처리하지
않으며, 여러 전략이 같은 자료를 사용했다고 독립된 근거가 늘었다고 판단하지 않는다.

KIS 장중 추정 수급은 개인 값을 제공하지 않으므로 개인 수급이 필수인 두 규칙을
활성화하지 않는다. 기관 추정은 10:00부터 제공된다. 공식 추정 구간 사이에도 이 단기
모델의 10분 원천 제한을 늘리지 않으므로, 모든 장중 시간에 수급 판단이 가능한 것은 아니다. 기간 누적 수급·레버리지 상품 수급·복합 거래량 규칙 다섯 개도 별도 검증이 필요하다.
ATR 손실 기준, 여러 거래일의 종료 시계, 돌파/추세 지속 전략, 비용 반영 성과 검증은 별도 작업이다.
운영 배포와 결정론적 조건 검증을 성과 검증으로 표시해서는 안 된다.

검증은 `test_current_flow_rules.py` 및
`PYTHONPATH=python_service:python_service/tests python3 python_service/tests/native_current_flow_smoke.py`로
수행한다. 후자는 실제 원천 필드 → 모델 → ABox → TypeDB 단계 조건을 검사하며,
운영 그래프와 알림 경로를 사용하지 않고 자신이 만든 임시 DB만 삭제한다.

## V3 관찰 순서 연결

`rule-strategy-contract-v3`는 기존 국내·미국 단기 회복 전략의 시장 조건을
바꾸지 않고, RuleBox에 상태·전이 의미를 동결한 후속 계약이다. 이전 불변
배포를 보존하고 별도 후보 배포에서 V2 네 단계씩 8개를 V3로 대체한다.
후보 안의 이전 규칙은 enabled만 false로 바꾸고 조건과 계약을 보존한다.
정확한 선행 계약 8개 외에는 바꿀 수 없도록 배포 비교가 검사한다.
활성 단계 규칙 수는 그대로이며 같은 조건을 두 번 계산하거나 알리지 않는다.

- TypeDB가 현재 단계의 시장·모델·정규장·신선도 조건을 판정한다.
  decisions 모듈은 그 증명을 RuleBox의 전이표에 연결해 관찰 이력을 저장한다.
  이 이력 처리는 새로운 가격 판정, 투자 행동 선택, TypeDB 시간 관계 추론이 아니다.
- 알림 대상 선정 전에 계좌·종목·세계·배포·계약별 상태와 관찰을 MySQL에
  원자적으로 저장한다. 상태 변경 도메인 이벤트도 같은 트랜잭션에 기록한다.
  알림 생략·전송 실패·워커 재시작으로 앞선 관찰이 없어지지 않는다.
- 관찰 → 진입 조건 확인 → 취소/종료 조건 확인 → 재진입 조건 재검토를 구분한다.
  처음부터 진입 조건을 충족하면 그 확인부터 시작하며 과거 관찰이나 실제 매수를
  가정하지 않는다. 진입과 취소/종료의 동시 충족은 충돌이다.
- 취소 뒤 새 진입 조건은 **재검토**다. 앞선 취소 조건이 안 보이는 것만으로
  해제됐다고 판정하지 않는다. 이번 버전은 취소 조건 해제의 별도 증명을 추가하지 않는다.
- 계산 시각 대신 native 조건의 원천 시각으로 순서를 정한다. 과거 입력과
  같은 원천 시각의 상충 결과는 현재 상태를 덮어쓰지 않는다. 과거 재생에
  미래 상태를 돌려주지도 않는다. 시간대·원천 시각 누락 및 미래 자료는 제외한다.
- 연결 범위는 해당 시장의 같은 정규장 거래일이다. 다음 거래일은 이전 기록의
  참조만 보존하고 새 기준을 시작한다. 장중 관찰 공백은 연속 유지라고 표시하지 않는다.
  장외·자료 누락·단계 미관측은 취소나 해제의 증거가 아니다.
- 성공 영수증은 중복 발송 방지에만 사용한다. 발송되지 않은 상태 변경은
  현재도 해당 단계의 신선한 증명이 있을 때 다시 알릴 수 있다. 이미 보낸 상태를
  반복 계산한 것만으로 새 알림을 만들지 않는다. 발송 시 기존 신선도 검사를 유지한다.

알림은 앞선 확인 → 이번 확인, 연결의 의미, 핵심 측정값, 현재 가격/수익률,
다음 확인을 보여준다. 전체 관찰과 ABox·추론 세대 참조는 저장된 판단 기록에 남긴다.
상태 저장에는 해당 대상의 키 조회만 사용하며 추가 AI 호출이나 전체 이력 검색은 없다.

자동 주문 권한과 매매 시점 검증 완료 여부는 계속 false다. 수급 전용 전략,
전략 간 인과 관계, 여러 거래일의 보유 종료 시계, 거래 비용을 반영한 성과 검증은
이 변경에 포함하지 않는다. 코드 테스트와 실제 장중 전환·발송 관측은 구분한다.

검증: `test_strategy_scenarios.py`의 전이/시각/발송/재시작/경합/롤백/메시지
계약 및 `native_strategy_smoke.run(contract_override=...)`로 후보 계약을 실행한다.

## 운영 V2

사용자 승인(2026-10-23)에 따라 `rule-strategy-contract-v2`의 `live-observation` 네 단계 규칙을 운영 릴리스에 포함한다. 기존 V1 연구 제안이나 불변 배포를 수정하지 않고 새 릴리스를 등록·검증·승격한다. 국내·미국 시장별로 관찰, 진입 검토, 진입 근거 취소, 보유 종료 검토를 모두 가진다. 새 운영 전략은 가격 회복·장중 반전 모델의 조합이며, 수급 전용 모델이 포함됐다고 표시하지 않는다.

운영 활성화와 예측 성과 검증은 별도다. 실시간 TypeDB 판정과 실제 고객 알림을 활성화하지만, `tradeTimingQualified=false`와 자동 주문 권한 없음은 유지한다. 최대 보유 기간은 여전히 연구 목표이며, 구현되지 않은 거래일 종료 시계나 비용 반영 성과를 운영 결과로 가장하지 않는다.

- 입력 투영은 현재 규칙의 사용 여부와 무관하게 원천에 있는 종목→시장 `TRADED_IN` 관계를 보존한다. 이전·새 배포가 같은 사실을 비교하며, 없는 시장 관계는 만들지 않는다. 그래프 조립 캐시 v25는 이 관계가 빠졌던 과거 입력의 재사용을 막는다. 활성 규칙에서 파생한 후보 배포 스키마가 `marketSession`, `sourceAgeSeconds`를 물리 속성으로 제공한다.
- 정규장, 정확한 모델·가설·릴리스 연결, 기존 적격성과 원천 경과 600초 이내를 TypeDB에서 함께 검사한다. 이 10분은 현재 수집·추론·발송 경로의 유효 범위이며 최적 매매 시점이라는 뜻은 아니다. 발송 직전에도 원본 근거의 시각을 재검사한다.
- 별도 AI 호출 없이 기존 `investmentInsight` 발송 경로를 사용한다. 동일 계좌·종목·세계·전략 버전의 성공 영수증과 비교해 새로 확인된 단계를 알린다. 자료 누락·오래된 근거·장외로 조건이 안 보이는 것은 해제나 종료로 안내하지 않는다.
- 진입 조건과 취소/종료 조건이 동시에 성립하면 충돌을 명시한다. 알림은 단계 변화, 함께 성립한 규칙, 실제 근거 수치, 현재가·보유 수익률, 다음 확인 조건을 보여준다. 상세 증거는 기존 웹 기록에 보존한다.
- 기존 시장 규칙과 관리 제한은 유지한다. 새 단계가 기존 제한을 자동 해제하거나 매수·매도 명령을 만들지 않는다. 이전 배포는 정상 롤백 경로로 보존한다.

네이티브 smoke는 운영 V2를 대상으로 정상·장외·자료 만료·잘못된 시장/릴리스·부적격·일부 진입 조건 누락을 실제 TypeDB에서 검증한다. 합성 테스트와 실제 후보 배포의 데이터 검증은 구분한다.

## 연구 V1

`rule-strategy-contract-v1`은 개별 규칙을 관찰·진입 검토·진입 판단 취소·보유 종료 검토의 네 단계로 묶는 동결 계약이다. 최대 보유 기간은 1~5 거래 세션, 신호 유효 기간은 30~3,600초다. 숫자는 계약 범위이며 추천 매매 설정이나 검증된 최적값이 아니다.

## 소유권과 실행

- 시장 데이터 모듈은 원천 시각과 측정값을 제공한다. 통계 모델은 정확한 가설 계약에 대한 근거만 생성한다.
- RuleBox의 `RuleClaimContract.strategyContract`가 전략 정의의 원본이다. 계약 지문, 원본 RuleBox 지문, 참조 모델의 규칙 지문·주장·실행 조건을 함께 보존한다.
- 설계·검증은 전역 기본 DB가 아닌 알림 담당 배포의 `graphStoreBinding`을 조회한다. 배포 ID와 DB 연결 식별자도 계약에 동결한다. 담당 배포가 달라지면 기존 제안을 다른 배포에서 조용히 검증하지 않고 `source-deployment-changed`를 반환한다. 배포 연결이 없으면 기본 DB로 대체하지 않는다.
- 등록되어 활성화된 정확한 `HAS_MODEL_SIGNAL` 모델 중 장중 원천 시계가 구현된 가격·수급 릴리스만 선택한다. 비활성·미등록·장중 시계 미지원 모델은 설계 카탈로그에서 제외 사유와 함께 표시한다. 현재 원천 시계가 없는 기업·이벤트·시장 간 모델을 장중 조건으로 가장하지 않는다. 수급 전용 모델이 없으면 가격 모델을 수급 모델이라고 대체하지 않는다.
- 각 단계의 모델 조건은 AND 결합이다. 모델 소유자가 실제 충족된 가설에만 생성하는 정확한 계약 노드를 사용하며, TypeDB가 시장·정규장·기존 적격성·원천 경과 시간을 검사한다. JSON 표시용 필드를 TypeDB 조건이라고 간주하지 않으며 전체 조건의 native profile은 ready여야 한다. 네 개의 비활성 후보 규칙으로 컴파일하며, RuleBox 구조 검증은 일부 단계만 활성화하는 것을 거부한다. 컴파일러 버전도 계약 지문에 포함한다.
- 시장 범위는 기존 `TRADED_IN` 관계와 Market의 `ontology-id`로 확인한다. 물리 Stock 스키마에 없는 `market` 속성을 조회하지 않는다. 현재 ABox에서 시장 관계를 읽을 수 없으면 해당 단계는 미평가다. 배포 전 시장 관계와 모델 근거를 포함한 실제 ABox 검증이 필요하다.
- `Strategy` TBox 개념과 `VALIDATES_STRATEGY` 관계를 재사용한다. 각 단계는 예측 가설이 아닌 참고용 조건 관측이다. Python과 알림 렌더러는 투자 행동을 선택하지 않는다.
- 판단 기록의 `strategyObservations`는 동일 세계·ABox·추론 세대에서 TypeDB가 확인한 단계와 수치를 보존한다. 확인되지 않은 단계는 unknown이며, 진입과 취소/종료 조건이 동시에 확인되면 conflicting-conditions다.

## 작성·확인 경로

1. `GET /api/investment-strategy-proposals/design-catalog`에서 현재 RuleBox와 사용 가능한 모델 ID, 제외 사유를 읽는다.
2. `POST /api/investment-strategy-proposals/design`에 title, symbols, sourceRuleboxFingerprint와 strategyDesign을 제출한다.
3. strategyDesign은 market(KR/US), maximumHoldingSessions, signalValiditySeconds, phases(setup/entry/invalidation/exit의 모델 ID 배열)를 모두 포함한다. 원본 RuleBox가 바뀌면 제출을 거부한다.
4. 기존 전략 제안 상세 API에서 동결된 전체 계약을 확인하고, `/validate`로 네 단계의 현재 TypeDB 조건을 함께 검증한다. `strategyPhaseEvaluation`이 각 단계의 실제 쿼리 실행 여부와 누락 사유를 구분한다. 근거가 없어 쿼리가 생략된 경우 `not-evaluated`이며 조건 불충족이나 검증 성공으로 해석하지 않는다. 운영 RuleBox/InferenceBox는 수정하지 않는다.
5. 중앙 AI의 기존 RuleChangeCandidateProposalService에 trigger=short-term-strategy-design을 전달하면 같은 선택 계약으로 제안한다. 현재 추론 완료 여부에 종속되지 않으며 무거운 InferenceBox 조회도 하지 않는다. AI가 실행 규칙·새 임계값·성공 확률을 작성할 수 없다. 네 단계 묶음은 전략 제안 저장소에 보존하며, 진입 규칙 하나를 일반 후보로 배포하지 않는다. 일반 가설 연구와 별도 요청이다. 이 기능을 주기적으로 호출하는 새 스케줄러는 추가하지 않았다.

재현 가능한 네이티브 검증: `PYTHONPATH=python_service:python_service/tests python3 python_service/tests/native_strategy_smoke.py`. 임시 TypeDB에서 정상·오래된 자료·장외·부적격·다른 릴리스·진입 근거 일부 누락·다른 시장·저장된 원천 입력·단계별 단독 충족을 포함한 14개 사례와 두 종목을 함께 조회하는 3개 사례의 총 68개 실제 쿼리를 실행하고 임시 DB를 삭제한다. 통합 조회에서는 종목별 결과가 개별 조회와 같고 다른 종목의 누락 근거·신선도를 빌려 쓰지 않는지도 검증한다. 운영 그래프와 알림을 변경하지 않는다.

## V1의 사용 범위

V1은 연구용 계약과 조건 판정 경로다. 현재 자료에서 조건이 맞았다고 매매 전략이 검증된 것은 아니다. 구조 검증만으로 전략 상태를 validated/approved로 승격하지 않으며 forceApproved도 매매 권한을 만들지 않는다. 자동 주문과 고객 매매 지시는 생성하지 않는다.

운영 적용에는 시장 관계가 현재 ABox에 연결되고 모델 근거의 `marketSession`, `sourceAgeSeconds`가 해당 배포의 물리 TypeDB 스키마와 입력에 제공되어야 한다. 컴파일러의 `nativeReasoningProfile=ready`는 문법·필드 매핑 지원을 뜻하며 배포 스키마·자료 준비 완료를 뜻하지 않는다. 공유 지식의 시장 관계를 가져오는 경로와 필요한 시각 속성은 후보 배포에서 함께 검증해야 한다. 현재 배포에 직접 스키마나 사실을 덧붙여 검증을 통과시키지 않는다.

거래 세션 기준 최대 보유 기간은 검증 목표로 저장한다. 실제 진입 영수증부터 거래 세션을 세는 종료 시계, 체결 가능 가격, 수수료·세금·스프레드·슬리피지, 독립 표본의 순수익, 시장 국면별 비교, 미래 모의거래, 발송 지연 검증이 남아 있다. 원래 가설의 outcomeContract는 모델 출처로 보존하며, 이를 전략 전체의 순수익 검증으로 대체하지 않는다. 이 경로들을 구현·검증한 후 별도 계약 버전과 배포 검토를 통해 매매 권한을 도입해야 한다.

기존 운영 RuleBox와 기존 알림 영수증은 다시 쓰지 않는다. 소스 코드 추가만으로 실행 중인 불변 배포에 새 전략을 삽입하지 않는다.

## 원천 시세의 장 구분 보존

시장 데이터 수집 시 선택된 시세의 원천 시각·수집 시각·시장·장 구분을
`source-session-observation-v1`로 기존 시계열 메타데이터에 함께 저장한다.
조회 시 두 시각과 시장이 원본 행과 일치할 때만 사용한다. 통계 모델과
ABox가 이 장 구분과 별도로 계산한 원천 경과 시간을 TypeDB 조건에 전달한다.

원천 시각이 없거나 시간대가 없거나 미래인 자료, 이 기록이 없는 과거 행,
일봉은 조회 시 정규장 자료로 바꾸지 않는다. 제공자의 휴장·종가 참고 상태가
표준 거래 시간보다 우선하며, 정규장 시세라도 장 마감 뒤 수집했다면 현재
정규장 자료로 쓰지 않는다. 미국 서머타임은 `America/New_York`를 사용한다.
기존 요일·세션 시간표와 제공자 상태를 사용하며 별도 거래소 휴일 달력은
추가하지 않는다. 과거 특징 스냅샷과 배포 바인딩은 변경하지 않는다.

가설 묶음을 다시 연결하는 동안 기존 판단을 유지하더라도, 이전 시세의
제한 사유를 다른 추론 세대의 미발송 원인으로 사용하지 않는다. 현재 자료
상태는 같은 세대의 판단 또는 원천 재확인 결과에 연결한다. 정상 자료의
연결 상태를 기록하는 것만으로 새 판단이나 자료 복구 알림을 만들지 않는다.

저장된 원천 입력 → 통계 모델 → ABox 전달을 검사하고, 원천에서 얻은
장 구분·경과 시간으로 실제 네이티브 쿼리를 실행한다. 시각 누락과 장 마감
이후 수집은 제외된다. 실제 발송은 기존 TypeDB 증명과 성공 영수증 비교를 따른다.
