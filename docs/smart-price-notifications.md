# 시간 구간을 사용하는 시세 알림

2026-10-15 사용자 승인에 따라 기존 `marketObservation` 사실 알림을 확장한다.
매매 판단, 가설 검증, RuleBox 의미나 배포 버전은 변경하지 않는다. 가격 사실은
기존 모니터 스냅샷과 TypeDB 후속 분석으로 이어지고, 발송은 기존 outbox를 사용한다.

## 이번 적용 범위

- 공급자가 제공한 시세 시각으로 최근 3·15·60분 가격 변동을 계산한다.
- 보유 종목의 기본 확인 기준은 각 구간 1.5·2.5·4%이며, 관심 종목에는 1.5배를
  적용한다. 누적 변동 알림도 관심 종목에는 기존 즉시 기준의 1.5배를 적용한다.
  이 숫자는 조정 가능한 초기 알림 정책이며 예측 정확도가 검증된 투자 기준이 아니다.
- 비교 구간이 실제로 4분이면 4분으로 표시하고, 3분 기준도 4/3배로 보정한다.
  부족한 시간 구간을 보간하거나 일간 변동률로 대체하지 않는다.
- 동일 움직임의 최초 감지, 추가 확대, 절반 이상 되돌림을 한 사건으로 관리한다.
  추가 확대는 최초 관측 변동폭에서 보유 1.5%p, 관심 2.25%p 단위로 확인한다.
  되돌림은 서로 다른 시세 관측에서 120초 이상 유지돼야 하며 추세 회복을 뜻하지 않는다.
- 시작 가격을 넘어 반대 방향의 급변 기준까지 충족하면 급반전으로 새 구간을 연다.
  단순 되돌림과 구분하며 앞 사건 ID를 보존해 같은 대화에서 이어서 보여준다.
- 사건 내 같은 단계는 반복하지 않는다. 확대·되돌림·급반전은 최소 1분 간격으로 일반
  10분 반복 제한보다 먼저 전달할 수 있다. 최초 감지는 기존 반복 간격을 유지한다.
  계좌 방해 금지, 메시지 활성화, 수신처와 사용자 지정 발송 정책은 유지한다.
- 동일 사건의 후속 메시지는 성공한 원본 전송 영수증의 수신처별 메시지에 답글로
  연결한다. 원본이 아직 전송 대기 중이면 후속도 기다린다. 다른 사건·계좌·종목은
  대화를 공유하지 않는다. 기존 관계·AI 후속 분석의 source-event 연결도 유지한다.
- 보유 종목에는 현재 수량을 고정한 가격 효과를 표시한다. 환율의 근거가 없으면
  원화 효과와 계좌 비중을 추측하지 않고 현지 통화 효과만 표시한다. 계좌 영향의
  분모는 현재 계좌 평가액이며 실제 기간 손익과 구분한다. 관심 종목에는 보유 손익을
  표시하지 않는다. 보유·관심 중복은 보유 기준으로 한 번만 처리한다.
- 시세 표시 시각은 KST이며, 이벤트에는 변경하지 않은 출처 시각과 가격을 보존한다.
  과거 비교의 시간대는 시장 현지 시간 구간과 해당 시간대 이름을 명시한다.

## 기록과 정확성

`marketPriceObservations`는 계좌 모니터 스냅샷에 종목당 최근 75분, 최대 90개
분 단위 관측을 유지한다. 같은 분의 마지막 관측과 실제 수집한 고가·저가·발생 시각,
첫 관측 시각·관측 횟수만 보존한다. 실제 수신 빈도가 기준보다 낮으면 짧은 구간은 사용 불가 상태로 남는다.
초기 배포 후 자료가 쌓이는 동안 기존 누적 변동 경로가 계속 작동한다.
급변 사건 진행 중 출처 시각 검증이 불가능해지면 그 사건을 이유로 기존 누적 알림을
막지 않는다. 짧은 구간을 검증할 수 없는 것과 누적 가격 변화가 없는 것은 다르다.

공급자 시각이 없는 조회 시각 폴백, 종가 참고값, 미래 시각, 유효하지 않은 가격은
급변 구간을 만들지 않는다. 시세 시각의 반복은 새 관측으로 세지 않는다. 동일 시각의
가격 수정은 별도 상태로 남기며 급변으로 취급하지 않는다. 3분 초과의 관측 공백,
통화·공급자·거래 구간·현지 거래일·가격 조정 기준·전일 종가의 변경은 경로를 끊는다.
분할 등 기업행동의 모든 유형을 탐지하는 구현은 아니며, 공급자가 변경 사실을
표시하지 않는 가격 불연속까지 자동으로 판별한다고 보장하지 않는다.

사건 상태 `marketPriceEpisodes`는 동일 모니터 트랜잭션에서 저장한다. 관측 상태와
outbox 접수 순번을 분리하고, 실제 enqueue 성공 때만 순번을 갱신한다. 접수는
발송 성공이 아니다. 발송 영수증과 재시도는 기존 알림 계층이 소유한다.
동시 작업자는 잠근 최신 사건 ID·순번·출처 시각과 비교해 오래된 후보를 거절한다.
전송에 실패한 원본은 기존 재시도 절차를 따르며, 재시작으로 기준이 초기화되지 않는다.

출처 경로, 정책 버전, 구간별 시작/끝 가격과 시각, 샘플 수, 사건 ID·순번을
알림 입력에 보존한다. 과거 알림을 새 정책으로 다시 작성하지 않는다.

## 설정과 검증

기본 활성화는 `marketObservationSmartEnabled=1`이다. `0`으로 바꾸면 기존 경로를
사용한다. `marketObservation3mChangePct`, `marketObservation15mChangePct`,
`marketObservation60mChangePct`, `marketObservationWatchlistMultiplier`,
`marketObservationExpansionStepPct`로 초기 정책을 조정한다. 기존
`marketObservationRawDeliveryMode=disabled/typedb-first`에서는 새 직접 발송도 하지 않는다.

`test_smart_price_observations.py`에서 급변, 느린 누적 변화, 기록 공백, 종가 참고값,
시계 역행, 같은 시각 수정, 보유/관심 차이, FX 누락, 확대·되돌림·재감지,
동시 작업자, persistence 및 실제 monitor 경로를 검증한다.
`test_investment_conversations.py`는 DB와 가짜 전송 영수증으로 같은 사건의 답글
연결을 확인하며 실제 사용자에게 테스트 알림을 발송하지 않는다.

종목별 과거 변동성에 따른 감지 기준 조정, 같은 시간대 상대 거래량, 지수·업종 대비 움직임,
계좌 전체 동반 하락 묶음, 관심 가격/연구 조건은 다음 확장 범위다. 이번 알림에
확인되지 않은 이 항목들을 표시하지 않는다. 이후 정책 검증에는 시간순 재생과
발송 없는 관찰에서 감지 지연·중복·급변 누락을 측정해야 한다.

## 보유 시세 알림의 금액 구분 (2026-10-21)

- `매입가 대비 평가손익`: 알림의 현재가에서 평균매입가를 뺀 값에 현재 수량을 곱한 미실현 손익이다. 수수료·세금을 제외한 현지 통화 기준이며, 실현 손익이나 증권사의 비용 차감 손익으로 표시하지 않는다. 평균매입가가 없으면 확인 불가로 표시하고 0으로 채우지 않는다.
- `이번 가격 변동분`: 기존 `positionPriceEffect.nativeAmount`를 그대로 보존한다. 누적 알림은 알림 기준가, 빠른 변동 알림은 변동 시작가와 비교한다. 현재 수량 고정의 가격 기여분이며 총손익이 아니다.
- 원화 가격과 손익은 원 단위로 표시한다. 외화는 필요한 센트까지 유지하고 불필요한 끝자리 0을 생략한다. 원시 값과 비교·감지 기준은 반올림하지 않는다.
- 시세 변화 후 기존 저장 스냅샷 사건과 추론 작업 계보를 통해 규칙을 재평가한다. 가격 변화 자체가 규칙 성립·해제나 후속 발송을 보장하지 않는다. 안내 문구는 의미 있는 변화가 확인된 경우의 발송만 설명한다. 이미 발송된 본문은 재작성하지 않는다.


## 2026-10-24 시세 출처와 기준값 보호

- KIS 마감 참고값은 시각이 오래된 경우에도 이미 관측한 실제 체결가격을 덮어쓰지 않는다. 표시된 가격이 오래되면 그 원래 시각과 상태를 유지한다.
- KIS 체결 프레임의 영업일(`BSOP_DATE`)과 체결 시각(`STCK_CNTG_HOUR`)을 결합해 `provider-execution` 시각으로 저장한다. 수신 시각은 별도로 남긴다. 미래·누락 시각은 검증된 체결 시각으로 취급하지 않으며, 오래되거나 검증되지 않은 프레임이 기존 검증된 체결을 되돌리지 않는다.
- 호가 프레임은 체결가격의 시각·출처·신선도를 갱신하지 않는다. REST와 병합된 데이터에서도 실제 선택한 체결가격과 해당 체결 단계의 시각을 함께 사용한다.
- 누적 변동 경로에도 빠른 감지와 동일한 실제 시세 검증을 적용한다. 마감 참고값, 조회 시각 대체값, 미래·180초 초과 가격은 발송 및 알림 기준값 갱신 대상에서 제외한다. 정상 시간외 체결은 실제 시각이 검증되면 허용하며 전역 정규장 제한을 켜지 않는다.
- 알림은 가격·종목·통화·출처 시각의 작은 `quoteWitness`를 가지고 outbox 승인 시 다시 검증한다. 잘못된 후보는 기준값을 갱신하지 않는다.
- 기존 무검증 누적 알림 기준값은 다음 정상 시세 저장 시 `verified-trade-baseline-v1`로 한 번 재설정한다. 재설정 사유와 시각을 남기며 재설정 자체는 발송하지 않는다. TypeDB 추론 완료 기준과 기존 대기 작업은 별도로 유지한다.
- 회귀 검증은 16,430 → 마감 참고 18,020 → 실제 16,400 및 152,800 → 마감 참고 160,000 흐름, 정상 누적 변동, 체결 시각 기반 빠른 감지, 오래된·미래·누락 프레임, 호가 갱신, 기준값 재설정과 outbox 검증을 오프라인 재현한다. 실제 투자 알림이나 유료 AI 호출을 만들지 않는다.

## 시세 맥락과 관측 지표 (2026-10-24)

- 참고 데이터를 반복 병합해도 선택한 실제 가격의 검증 근거를 유지한다. 체결 시각이 없거나 미래인 첫 WebSocket 프레임은 기존 검증된 계좌 가격을 대체하지 않는다. REST가 캐시의 최상위 시각을 바꿔도 체결 단계의 검증 근거를 보호한다.
- `price-context-v1`은 기존 시세 알림에 동결하는 산술 표시 계약이다. 감지 임계값, 매매 의미, TypeDB 판단, AI 호출 조건을 추가하지 않는다. 과거 성공 발송과 부분 전송 본문은 변경하지 않는다.
- 동일 종목·가격·실제 체결 시각이 일치하는 KIS 체결 프레임의 시가·고가·저가를 정규장 시각에만 사용한다. 실제 선택한 가격과 출처가 다르거나 값이 불완전하면 공급자 당일 수치를 붙이지 않는다.
- 공급자 시가가 있으면 시가 이후 변동을 표시한다. 스냅샷의 전일 종가로 계산한 등락률이 같은 체결 프레임의 전일 대비 등락률과 0.05%p 이내로 일치할 때 개장 갭과 전일 대비 변동도 구분한다. 값이 없거나 맞지 않으면 갭은 표시하지 않는다. 각각의 분모가 달라 두 수익률을 더하지 않는다. 공급자 시가가 없을 때 첫 수집 가격을 시가로 간주하지 않는다.
- 전체 당일 자료가 없으면 `금일 관측 구간`의 고저점과 관측 시작 시각을 표시한다. 표본 사이 고저점은 미확인이다. 날짜·거래 구간·통화·출처·가격 조정 기준이 바뀌면 범위를 초기화한다. 연속 자료가 있는 최근 약 15분 표본 범위를 벗어났을 때만 해당 범위와 시각을 덧붙인다.
- 과거 비교는 통화·출처·거래 구간·조정 기준이 같고, 비교 구간의 시작이 같은 현지 2시간 구간(00~02시, 02~04시 등)에 속하며, 실제 구간 길이 차이가 현재 길이의 10% 이내인 표본만 사용한다. 미국은 해당 날짜의 서머타임을 반영한다. 현재 길이와 과거 길이 범위, 현지 시간대를 함께 표시하며 수익률을 임의 환산하지 않는다. 현재 구간과 겹치거나 이후인 표본은 제외한다. 최소 20개 구간과 3개 현지 거래일이 있어야 과거 보관 구간 중 현재 변동폭보다 작은 비율과 절대 변동률 중앙값 대비 배수를 표시한다. 예측 확률이나 전체 시장 통계가 아니다. 자료가 부족하면 시간대 조건을 완화하지 않고 `자료 축적 중`으로 표시한다.
- `marketPriceContext`는 종목별, 3·15·60분별 최근 45일 이내 최대 288개 비교 표본을 저장한다. 시간대별 비교 표본을 확보하도록 기존 20일·96개 한도를 제한적으로 확대한다. 현지 거래 구간·시간 슬롯당 최초 유효 비중첩 구간 하나만 추가해 반복 수집의 중복 가중을 제한한다. 거래 구간이 바뀌어도 구간 표시가 있는 과거 표본을 보존하고 비교할 때 같은 구간만 선택한다. 과거 자료를 소급 생성하지 않으며, 표본 한도로 부족하면 미확인 상태를 유지한다. 이 이력은 AI 입력에 추가하지 않는다.
- `marketPriceDiagnostics`에는 KST 날짜별 수집 평가 상태와 후보·outbox 접수·제외 사유 건수를 저장한다. 단위는 `종목×모니터 주기`이며 같은 원천 재조회도 `unchanged-source`로 구분한다. 실제 수집 시작·마지막 시각을 남기며 관측 공백을 정상 가동으로 간주하지 않는다. 같은 스냅샷 재시도는 중복 집계하지 않는다.
- `npm run python:monitor:status`에서 저장된 날짜별 관측 지표를 확인한다. `npm run python:notifications:status`의 `price_observation_delivery`에는 최근 보관된 최대 100개 시세 알림의 상태와 전달 지연을 표시한다. 전체 누적 통계가 아니다. 알림 ID를 먼저 제한하고 25개씩 필요한 JSON 필드만 읽는다.
- 지연은 `is_mock=0`, `data_quality=actual`, `audience=account`, `channel=accountNotification`, `status=delivered`, `receiptVerified=true`가 모두 확인된 첫 전달 영수증을 기준으로 계산한다. 접수→영수증과 원천 시각→영수증의 표본 수·중앙값·95백분위·최댓값을 구분한다. 영수증이나 시각이 없는 경우 0초 성공으로 채우지 않는다. `doneWithoutVerifiedReceiptJobs`는 처리 완료 중 검증된 전달 근거가 없는 작업 수이며, 영수증 보관 한계 등이 있으므로 전송 실패 수로 간주하지 않는다.
- 검증은 반복 병합, 첫 미검증 체결, REST 혼합 캐시, 개장 갭 산술, 부분 관측, 거래일·계좌 변경, 과거 비교 표본 부족·미래·겹침, 중복 집계, 실제 영수증 필터와 제한된 SQL 조회를 발송 없는 합성 자료로 수행한다. 실제 장중 표시와 신규 전달 성과는 배포 후 관측 대상이다.

## 전달 집계 및 메시지 보완 (2026-10-24)

- 이전 집계가 `accountNotification`을 audience와 비교하던 오류를 수정했다. 실제 전송기의 audience는 `account`, channel은 `accountNotification`이다. 테스트도 실제 dispatch가 만든 필드와 영수증으로 집계를 검증하며 운영 채널·미검증·실패 영수증을 제외한다.
- 읽기 전용 확인에서 최근 보관된 실제 작업 5건 모두 검증된 고객 전달이 확인됐다. 기존 0건 표시는 집계 오류였다. 이 표본의 접수→영수증 중앙값은 약 32.4초, 최댓값은 약 48.1초였다. 5건 모두 원천 시각 지연 계산 자료가 없어 시세 발생→전달 지연이나 새 배포 성과로 해석하지 않는다.
- 분별 고저점은 실제 수집한 가격만 사용한다. 동일 시각 재조회·수정은 횟수나 고저점을 늘리지 않는다. 75분·90개 상한과 기존 관측 공백 초기화는 유지한다. 비교 시작 이전에 발생한 첫 분의 고저점은 해당 구간 고저점에서 제외한다. 구간 수익률의 분모·감지 임계값은 기존 마지막 관측 가격 그대로다. 수집하지 못한 틱은 복원하지 않는다.
- 빠른 변동과 누적 변동 메시지는 변동폭·현재가·현재 수량 고정 가격 효과를 먼저 표시한다. 확대·되돌림 후속에서는 반복되는 평균매입가·과거 비교 대기·전체 창 나열을 생략한다. 초기/급반전은 감지된 시간 창의 과거 비교를 우선 표시하고, 전체 산술 사실은 동결한 `priceMovement`·`priceContext`에 보존한다. 이전 전달 본문이나 부분 전송 메시지는 재작성하지 않는다.
- 공급자 고가·저가가 동시에 갱신되면 둘 다 표시한다. 고가 대비와 저가 대비 변동률도 구분한다. 모든 보완은 가격 사실 표시와 진단에 한정하며 새 AI 호출·투자 행동·테스트 고객 알림을 생성하지 않는다.
